# ADIX MEDIA — نظام الوكلاء المتكامل

## 📋 الملاحظات: بناء مواقع مخصصة لكل عميل

### المتطلبات الأساسية لكل موقع:

| الحقل | مثال | واجب؟ |
|-------|------|--------|
| اسم الشركة | وزيرا الكهرباء | ✅ |
| الشعار | logo.png (SVG/PNG) | ✅ |
| الألوان | #1A73E8 | ✅ |
| الوصف | متاجر إلكترونية موثوقة | ✅ |
| المنتجات | اسم \| السعر \| الصورة | ✅ |
| الاتصالات | هاتف، بريد، واتساب | ✅ |

### وظائف الوكلاء:

| الوكيل | الوظيفة |
|-------|----------|
| وائل (المدير) | توجيه الوكلاء، المتابقة |
| التنفيذ | بناء المواقع HTML/CSS/JS مخصصة |
| المحتوى | صمد الصور، النصوص الوصفية، الميتا |
| الرصد | مراقبة الأداء (SEO، سرعة، مثبت) |
| المبيعات | عروض باقات، تبادلات، متابعة |
| المالية | حساب السعر، الفاتورة، التسوية |

### الهدف:

بناء نظام قادر يولّد **متاجر إلكترونية مخصصة** فورًا، مبنية على:

- بروتوتايبات premium (نمط betternights + aether1)
- Dark mode (#0b0d17 + accent #FFA500)
- Responsive متكامل
- سيو داخلي محسّن
- صور عالية الجودة (باستخدام Gemini API)

### خطوات التنفيذ:

1. ✅ جمع المتطلبات (اسم، ألوان، منتجات، شعار)
2. ✅ بناء معاينة تفاعلية مدمجة (single-file HTML مع CSS+JS مدمج) للعرض السريع على العميل — يُرسل كرابط raw جديد قبل النشر النهائي
3. ⏳ توليد CSS مخصص للعلامة التجارية
4. ⏳ بناء HTML ديناميكي للمتجر
5. ⏳ رفع صور المنتجات لخدمة CDN
6. ⏳ النشر على Vercel (subdomain تلقائي)
7. ⏳ تفعيل SEO تلقائي
8. ⏳ متابعة الأداء اليومي

### بروتوكول الموافقة البشري (Human-in-the-Loop):

قبل أي اتصال مبيعات نهائي، يجب إرسال تقرير الموافقة إلى المالك (أحمد) عبر Telegram بصيغة:
- اسم العميل ونوع نشاطه
- الخدمة / السعر (50$ ثابت كحد أدنى لاختراق السوق)
- رابط المعاينة (Vercel أو raw مؤقت)
- القرار: `/approve` أو `/revise` أو `/delete`

لا يبدأ وكيل المبيعات بالاتصال إلا بعد الموافقة الصريحة.

**استخدام:**

```bash
# بناء موقع لعميل جديد
npx adix-media build --client "اسم العميل" --colors "#HEX,#HEX" --logo "url.png"

# قائمة العملاء
npx adix-media list-clients

# حالة أحد المواقع
npx adix-media status --site client-name.vercel.app
```
